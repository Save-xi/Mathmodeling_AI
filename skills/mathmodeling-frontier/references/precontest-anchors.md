# 赛前文献与算法锚定，赛时按题型补漏

赛前完成宽范围检索和条件筛选，把工作沉淀为可离线调用的锚点。赛时先匹配原题与数据，再核对遗漏。锚定对象是“任务结构 + 数据条件 + 可检验的增量”，不是赛题字母、某个年份冠军算法或一张通用排行榜。

## 调用方式

唯一维护的机器可读目录是 [algorithm-anchors.json](algorithm-anchors.json)。用 [lookup_anchors.py](../scripts/lookup_anchors.py) 提取相关路线和所引用的证据；不要整体读取 JSON，也不要同时加载两份历史快照。

```powershell
$frontierSkill = Join-Path $HOME ".codex\skills\mathmodeling-frontier"
python -X utf8 "$frontierSkill\scripts\lookup_anchors.py" --list
python -X utf8 "$frontierSkill\scripts\lookup_anchors.py" --task forecast --task predict-optimize --format markdown
```

命令只读本地目录，无网络、无写入、无自动排名。可用 `--format json` 供后续程序使用。`--check` 仅检查目录结构与证据引用，不证明论文或算法正确。

| route ID | 先按这些问题特征选择 |
|---|---|
| tabular | 独立样本的回归/分类；规模、混合字段、类别不平衡 |
| forecast | 时间顺序预测；预测步长、周期、协变量可用时点 |
| panel | 多实体重复观测；已知实体未来与新实体外推分开 |
| causal | 处理/政策效应；识别设计、时间顺序、干扰与重叠 |
| spatiotemporal | 有真实空间/网络关系的动态预测 |
| network | 路径、网络流、设施、路由；先区分图优化和图学习 |
| optimization | 排程、分配、布局与离散/连续约束优化 |
| predict-optimize | 预测参数进入下游决策；误差与实际决策损失可能错位 |
| robust | 不确定参数、风险、随机或分布鲁棒决策 |
| uncertainty | 区间、联合事件、多步轨迹或在线校准 |
| dynamics | ODE/PDE、参数反演、机理失配或重复仿真 |
| symbolic | 题目要求公式、可解释关系或动力学方程发现 |
| multiobjective-bo | 多目标取舍，或评价昂贵的黑盒实验 |
| simulation | 排队、事件、传播、蒙特卡洛与全局敏感性 |
| control | 多步反馈决策；可信状态转移和闭环验证 |
| evaluation-clustering | 综合评价、偏好不确定、无标签分群及稳定性 |

一道题可以用两个互补路线，例如 forecast + predict-optimize；一个算法不必每问都用。先选最相关的一至三个路线，遇到新的任务结构再局部补读。不得因为未命中路由就静默加载全部目录。

## 赛前准备做到什么程度

没有本届原题时，按问题族声明适用包络，而非拒绝工作。每张卡至少有：透明基线、机制与接口、候选升级、数据/资源前提、淘汰条件、最小验证、稳定来源、近期增量/负面证据、版本状态和赛时差分查询。对不值得追新的方向，可以明确保留成熟方法，不强凑 2026 算法。

准备时同时区分四层：

1. `PREPARED`：有日期的一手资料已核对，可供离线筛选；记录实际阅读到摘要、方法段还是完整实验。
2. 实现可得：明确代码、权重、许可证及版本；官方仓库存在不表示能离线运行。
3. 本机试跑：实际入口、环境、测试输入、耗时/峰值资源及结果；未运行就写 `NOT_RUN`。
4. 本题验证：题目契约、同信息/同预算比较、可行性与误差；赛前通用卡不能预先完成这一层。

本目录的 `PREPARED` 不等于 `PRIMARY`、已安装或已在 RTX 4060 8GB 上验证。论文上限也不是本机显存上限。正式采用前应读完与实现/保证相关的原文部分；若准备只读到摘要，卡片必须保留这个缺口。

**资源准备也要前移。** 依赖/平台检查、明确版本和许可、必要权重的离线准备、合成或历史数据上的小规模入口试跑和峰值资源测量，通常都能在没有本届原题时完成。在用户授权的准备范围内，优先完成拟保留的一至三个实现，而非下载全部模型。真实题目才决定最终样本形态、实际运行规模、信息边界与性能；不要把上述通用资源准备列为“必须等原题”。若本轮明确只读或禁止安装/下载，则写“本轮未执行，可在赛前准备”，不能改写成必须赛时才做。

## 赛时流程与检索范围

先用已有 `problem_map` / `model_contract` 写一行匹配：“本题条件 → anchor ID → 可用基线/增量 → 不满足条件 → 最短验证”。不另建大型档案。锚点提供起点，同时保留一个可能推翻它的机制解释或经典替代，避免为了套卡片曲解题目。

离线匹配后只查下列差分：

- **任务差分**：本题多了哪些硬约束、信息时点、数据形态或输出要求，现有卡能否覆盖；
- **证据差分**：关键假设、反例、负面结果或适用域没有核清；
- **版本差分**：将实际使用的实现/权重/许可证发生变化，或者用户明确要求“截至现在最新”；
- **遗漏差分**：是否漏了一个会改变选型的竞争路线。用机制词查询，不只搜索已选算法名。

每条选中路线复用卡里的两条定向 query，替换本题的机制、条件和时间范围。普通赛时初轮每个主要路线以 10–15 分钟为起始上限，合计通常不超过 30 分钟；已有证据足够且无当下最新声明时可以零检索。实际剩余时间更少时缩短预算。最多补一轮针对未解决关键点的查询；得到重复结果或不能改变决策即停止，不以“文献可能无限多”继续搜索。

字段发布时间、题面容量语义、数据是否修订等项目内部事实，先查原题/数据字典/原始记录；通用论文搜索不能查出本项目未提供的事实。对外查询只需抽象任务机制与有用条件，不粘贴当届整段赛题、独特数值组合或寻找现成解答。

只有库外结构、关键矛盾或基线的实质失败才进入更深入研究，说明原因与新增预算，保留论文时间；这属于正常建模判断，不新增实施审批。赛中资料获取还需遵守当前国赛规则，不能搜索当届赛题讨论、现成解答或向队外人员求助。

## 来源与版本怎么复用

- 保留原始 `verified_at`、题名、作者、发表状态、URL 和实际阅读范围，离线调用不更新核验日期。
- 对原论文、预印本、代码版本和新模型发布分别记账。同系列 2024 论文不能替 2026 新权重证明新架构、许可或性能；作者基准结果不等于本题实测。
- 使用旧日期证据可以给有边界的建议，不能称为“今天已检索完整”。有定向补漏时只追加新增证据和改变的判断。
- 论文定理不会按固定天数自动失效；接口、权重访问、撤稿/修订和许可等变化会触发相应核对。不要用机械的每日全文刷新取代针对性判断。
- 若需 task-level 排名，把选中的资料映射到 [live-search-protocol.md](live-search-protocol.md) 的 schema v2，并在日志中写明 `ANCHOR_REUSE` 或 `GAP_REFRESH`。`live_search_verified=true` 只能表示引用的资料确实曾被联网核验，不能用文件存在或离线命中伪造该事实。目录保留 `verified_on` 日精度；旧日志没有精确时间时，不补造 schema v2 的 `verified_at`，继续无分数的条件匹配，或在真正需要排名时局部核验并记录真实时间。`SOFTWARE_RELEASE` / `OFFICIAL_DOCS` 映射为 v2 的 `OTHER`，不能改成同行评审论文以通过门槛。没有目标题时不生成假 baseline/假问题契约来争取 `PRIMARY`。

查询结果应紧凑交付：选中锚点、真实适配/冲突、基线与一个可检验增量、验证/预算、已做和未做的补漏。普通匹配不强制生成六个候选、整篇综述、整套 BibTeX 或多个实验管线。

未运行或契约仍为 `PROVISIONAL` 的路线用“建议先试、条件候选、回退”描述；不要把排序专用 `PRIMARY/BACKUP` 重定义为普通行动优先级。它们在本 Skill 中有既定证据门，不能用一句“只是优先级”绕过。
